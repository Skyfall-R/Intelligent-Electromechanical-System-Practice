# 02 · 调试协议（主控 ↔ 上位机）

> 配套 `01-接口约定.md`。那份管 **视觉↔主控**，这份管 **主控↔电脑上位机**。
> 两份都改动时必须同步通知全组。
>
> 版本 **v3**，2026-08-25。
> v3 按队友要求把运动指令改成**数字动作码**（00 刹车 / 01 直行 / 02 左移 /
> 03 右移 / 04 左转 / 05 右转），v2 的连续速度指令 `S,<vx>,<vy>,<w>` 已删除；
> 运动逻辑抽成独立模块 `firmware/Core/Src/motion.c`。

---

## 0. 一句话

蓝牙串口上跑 **ASCII 行协议**：主控 20 Hz 往上位机推一行遥测，上位机随时往下发单行命令，每行末尾带一个异或校验。

---

## 1. 物理层

| 项 | 值 |
|---|---|
| 主控侧 | **USART2 完全重映射：PD5 = TX、PD6 = RX** |
| 模块 | HC-05，名字 `CAR_DBG`，配对码 `1234`，ROLE=0（从机） |
| 波特率 | **115200**，8 数据位，无校验，1 停止位 |
| 电脑侧 | 蓝牙配对后的**「传出」**虚拟串口（本机是 `COM13`） |

> HC-05 的 VCC 只能给 **5 V**（下限 3.6 V），逻辑电平 3.3 V，接 STM32 直连、不用电平转换。

---

## 2. 为什么用文本而不是二进制帧

跟视觉链路**故意做相反的选择**：

| | 视觉链路（OpenMV，二进制定长帧） | 调试链路（蓝牙，ASCII 行） |
|---|---|---|
| 谁在读 | 机器对机器 | **人在读** |
| 频率 | 25 Hz，要省带宽 | 20 Hz，带宽富余 |
| 出错时 | 只能靠调试器猜 | **肉眼直接看懂** |
| 手动测试 | 得写脚本 | **串口助手打一行就能测** |

调试通道的第一属性是"出问题时你能看懂"，为这个牺牲一点带宽非常划算。

**带宽核算**：遥测行约 126 字节 × 20 Hz = **2.5 KB/s**，占 115200 bps 的 22%。HC-05 的 SPP 实测吞吐通常 3～8 KB/s，留有余量。

---

## 3. 行格式通则

```
<类型字符> [ , <字段> ]* * <校验> \n
```

- **行尾** `\n`（0x0A）。`\r` 一律忽略，所以 `\r\n` 也能用。
- **校验** `*` 后跟**两位大写十六进制**，等于**行首到 `*` 之前所有字符的逐字节异或**（不含 `*` 本身）。
- 行内**不允许**出现 `\n`、`*`（校验位除外）。
- **单行最长 160 字节**，超长整行丢弃。
- 校验不通过 → **整行丢弃**，只累加错误计数，**不回错误日志**（否则线路差时会互相刷屏）。

### 校验计算示例

对 `E`：`0x45` → 校验 `45`，完整行是 `E*45\n`

C 语言实现：

```c
static uint8_t line_xor(const char *s, uint16_t n)
{
    uint8_t c = 0;
    for (uint16_t i = 0; i < n; i++) c ^= (uint8_t)s[i];
    return c;
}
```

### 向后兼容规则（重要）

- **新字段只允许追加在行尾。**
- 接收方解析时：**字段数不足 → 丢弃整行；字段数超出 → 忽略多余的。**

这样一端升级了另一端不用同步改，不会互相打架。协议版本号在 `V` 帧里报。

## 4. 上行：主控 → 上位机

### 4.1 `T` 遥测帧（20 Hz）

```
T,<1>,<2>,...,<27>*XX
```

| # | 字段 | 类型 | 单位 / 含义 |
|---|---|---|---|
| 1 | `ms` | uint32 | 主控运行时间，ms |
| 2 | `cnt_lf` | int16 | **左前**轮：一个 motion tick（12 ms）的编码器计数 |
| 3 | `cnt_lb` | int16 | **左后**轮 |
| 4 | `cnt_rf` | int16 | **右前**轮 |
| 5 | `cnt_rb` | int16 | **右后**轮 |
| 6 | `duty_lf` | uint8 | **左前**轮 PWM 占空 0~100 |
| 7 | `duty_lb` | uint8 | **左后**轮 |
| 8 | `duty_rf` | uint8 | **右前**轮 |
| 9 | `duty_rb` | uint8 | **右后**轮 |
| 10 | `yaw_c` | int16 | IMU 航向 ×100 度（相对值） |
| 11 | `vis_class` | uint8 | 0 无 / 1 红方块 / 2 黄圆柱 / 3 目标区 |
| 12 | `vis_bear_c` | int16 | 视觉方位角 ×100 度，左负右正 |
| 13 | `vis_dist` | uint16 | 视觉距离 mm，**65535 = 无效** |
| 14 | `vis_conf` | uint8 | 置信度 0~100 |
| 15 | `vision_lost` | uint8 | 0/1，100 ms 无视觉帧置 1 |
| 16 | `tof0` | uint16 | ToF ①，mm，**0 = 无效/超量程** |
| 17 | `tof1` | uint16 | ToF ② |
| 18 | `tof2` | uint16 | ToF ③ |
| 19 | `intake` | uint16 | 入料口累计计数 |
| 20 | `state` | uint8 | 任务状态 1~10（见 §7） |
| 21 | `n_col` | uint8 | 已收数量 |
| 22 | `fault` | uint8 | 故障位（见 §8） |
| 23 | `cmd_code` | uint8 | **当前生效的动作码 0~5**（见 §5.1） |
| 24 | `srv_rail` | int16 | 导轨舵机当前值 |
| 25 | `srv_knob` | int16 | 拨轮舵机当前值 |
| 26 | `srv_push` | int16 | 推杆舵机当前值 |
| 27 | `mode` | uint8 | 0 = AUTO，1 = MANUAL，2 = ESTOP |

**⚠️ v3 改了轮速字段的单位**：v2 里 `v_lf~v_rb` 是 mm/s，v3 换成
**每 12 ms 的编码器计数** `cnt_lf~cnt_rb`，并且已经折算成「期望方向为正」
（反转的轮子读到负计数会取反）。

这么改的理由：闭环直接控的就是这个计数（目标值 `SPD_TARGET` 默认 11），
调试时曲线和目标线可以直接对照。折成 mm/s 要乘 `WHEEL_R_MM`、除 `ENC_PPR`，
这两个参数本身还没标定，先换算只会把标定误差混进观测量里。
`duty_*` 四个字段是配套的：占空比顶到 100 还追不上目标，说明是负载/电池问题，
不是控制参数问题——这是这套积分控制律最常见的故障，光看计数看不出来。

结构体字段名也一起改了（`v_lf` → `cnt_lf`），这是故意的：
让单位变化在编译期就报错，比运行时悄悄按 mm/s 解读安全。

**⚠️ 轮序命名坑**：队友代码里 `LEFT_FORWARD` / `LEFT_BACKWARD` 指的是**左前轮 / 左后轮**，
不是"前进 / 后退"。协议里统一用 `lf / lb / rf / rb`，避免歧义。

**⚠️ ToF 三个的安装位置（前 / 侧 / 后？）还没定**，`tof0~2` 的语义等机械装配后确定，
在这里补一行说明。TOF400C-4M（VL53L1X）量程 4 m，覆盖 2×3 m 场地绰绰有余。

**没有超声波字段** —— 真实清单里 HC-SR04 数量为 0（仅供备用）。
`01-接口约定.md` §6c v4 那段"前向靠超声、侧向 ToF 会超量程"的论证**已经过时**：
ToF 换成 4 m 量程后，覆盖搜索的碰壁判据可以完全走 ToF。**那一节要跟着改。**

示例：

```
T,12345,11,11,10,11,42,43,45,44,-1523,1,-1234,850,90,0,1200,430,0,3,4,0,0,1,0,500,0,1*4A
```

### 4.2 `V` 握手帧

```
V,<fw_ver>,<proto_ver>,<sysclk_hz>*XX
```

上电后发一次；收到下行 `Q` 时也发一次，**紧接着把所有参数用 `K` 帧全部回读一遍**。

示例：`V,0.2.0,3,72000000*7E`

### 4.3 `K` 参数回读帧

```
K,<NAME>,<value>*XX
```

**每次收到 `P` 改参数后必须回一条 `K` 确认**——上位机据此更新界面显示，形成闭环。改失败（参数名不认识 / 越界）也要回 `K` 带**当前实际值**，让界面能自动纠正。

示例：`K,SPD_TARGET,11*42`

### 4.4 `L` 日志帧

```
L,<text>*XX
```

`text` 内**不得含** `,` `*` `\r` `\n`，长度 ≤ 100。

示例：`L,STATE 2->3*05`、`L,ESTOP BY HOST*26`

## 5. 下行：上位机 → 主控

| 命令 | 格式 | 说明 |
|---|---|---|
| **动作** | `N,<code>*XX` | **数字动作码 0~5**，见下 |
| 心跳 | `H*XX` | 遥控模式下保活，不改动作 |
| **舵机** | `J,<id>,<val>*XX` | id：0 = 导轨，1 = 拨轮，2 = 推杆 |
| 设参数 | `P,<NAME>,<value>*XX` | value 为 **int32**（见 §9） |
| 强制状态 | `G,<state>*XX` | 直接切到 1~10 某个状态 |
| 视觉模式 | `M,<0-3>*XX` | 转发给 OpenMV 的模式字（见 `01-接口约定.md` §2b） |
| 请求同步 | `Q*XX` | 主控回一条 `V` + 全部 `K` |
| 急停 | `E*XX` | 立刻停所有电机和舵机 |
| 回自动 | `A*XX` | 交还给状态机 |

### 5.1 `N` 数字动作码

```
N,<code>*XX
```

| 码 | 动作 | 含义 |
|---|---|---|
| `00` | 刹车 | 四轮短接刹车，占空比归零 |
| `01` | 直行 | 沿车头方向前进 |
| `02` | 左移 | 横向平移向左，**车头朝向不变** |
| `03` | 右移 | 横向平移向右 |
| `04` | 左转 | 原地逆时针 |
| `05` | 右转 | 原地顺时针 |

`00` 和 `0` 都接受（十进制解析，前导零不会被当成八进制）。
**超出 0~5 的码整行丢弃**并回 `L,BAD RANGE`——把看不懂的码悄悄当成刹车，
会把上位机的 bug 掩盖成"车怎么老是停"。

**速度不在指令里。** 四轮闭环的目标值由参数 `SPD_TARGET` 决定（默认 11，
即原 `main.c` 里写死的那个值），全局一档。要变速改参数，不改指令。

#### 5.1.0 可直接粘贴的整行（串口助手手测用）

不接上位机、只用 XCOM 之类的串口助手也能测。**发送时勾上"发送新行"**：

| 你要做的事 | 整行（含校验） |
|---|---|
| 刹车 | `N,00*62` |
| 直行 | `N,01*63` |
| 左移 | `N,02*60` |
| 右移 | `N,03*61` |
| 左转 | `N,04*66` |
| 右转 | `N,05*67` |
| 心跳（保持当前动作） | `H*48` |
| 读全部参数 | `Q*51` |
| 急停 | `E*45` |
| 回自动 | `A*41` |
| 故意发错（应回 BAD RANGE） | `N,6*54` |
| 故意错校验（应静默丢弃） | `N,01*00` |

⚠️ 只发一条 `N,01*63` 车会**只动 200 ms 就停**——心跳超时保险生效了，这是正常的。
要让它一直走，得每 200 ms 内至少补一条 `N,01*63` 或 `H*48`。

#### 5.1.1 四轮方向表

这张表是 `firmware/Core/Src/motion.c` 里 `WHEEL_DIR[]` 的文档副本，
两边必须一致。`+` 正转 / `−` 反转 / `0` 刹车：

| 码 | 动作 | 左前 | 左后 | 右前 | 右后 |
|---|---|---|---|---|---|
| 00 | 刹车 | 0 | 0 | 0 | 0 |
| 01 | 直行 | + | + | + | + |
| 02 | 左移 | − | + | + | − |
| 03 | 右移 | + | − | − | + |
| 04 | 左转 | − | − | + | + |
| 05 | 右转 | + | + | − | − |

#### 5.1.2 ⚠️ 这张表必须在真车上验一遍

符号取决于麦克纳姆轮辊子的实际朝向（X 型 / O 型）和装配方向。
**四个符号里错一个，横移就会变成原地打转**——这是麦轮车最常见的翻车点。

目前有两条旁证，来自同学原 `main.c`（已在真车上跑过）：

- 原 `mode 1`「直行」= 四轮全 Forward → 与本表 `01` 一致
- 原 `mode 2` = (+, −, −, +) → 与本表 `03`「右移」一致

剩下 `02 / 04 / 05` 是按标准 X 型麦轮推的，**没有实车旁证**。
（原 `mode 3` = (+, −, +, −)，不对应任何标准麦轮基本动作，看着像没写完的斜向平移，本表没采纳。）

验证办法，十分钟能做完：

1. 车架起来，四轮悬空，上位机连上，点「接管遥控」
2. 逐个发 `N,01` ~ `N,05`，每个看两件事：
   - 四个轮子的转向对不对（趴下去看）
   - 上位机「轮速」页四条 `cnt_*` 曲线**是不是都为正**。有一条常为负，
     就是那个轮子的方向符号反了，改 `WHEEL_DIR[]` 对应格子
3. 四个符号都对了再落地，重新走一遍确认整车运动方向

#### 5.1.3 没有后退码

同学给的动作集只有 6 个，**没有「后退」**。收集任务里抓完料要退出来、
撞墙要脱困，这两处目前无解。加的话是一行：

```c
/* 06 后退 */  {   -1,   -1,   -1,   -1 },
```

同时要把 `debug_link.h` 里的 `DBG_CODE_MAX` 改成 6、上位机加一个按键。
**要不要加请全组定**——这是接口约定，不该由某一个人单方面改。

### 5.2 `J` 舵机命令

```
J,<id>,<val>*XX
```

| id | 舵机 | `val` 含义 | 范围 |
|---|---|---|---|
| 0 | `SERVO_SLIDE_RAIL` 导轨 | 目标位置 | 待标定 |
| 1 | `SERVO_KNOB` 拨轮 | **连续旋转速度**（STS3032 轮式模式），负=反转脱困 | −1000 ~ +1000 |
| 2 | `SERVO_PUSH_ROD` 推杆 | 目标位置 | 待标定 |

三个都是飞特 **STS3032** 单轴 360° 磁编码总线舵机，经 URT-2 驱动板走串口
（导轨 + 拨轮 挂 UART4，推杆 挂 UART5）。

**`J` 命令只在 MANUAL 模式下生效**，AUTO 模式下由状态机控制，收到 `J` 回 `L,J IGNORED AUTO`。

## 6. 运行模式与安全机制

### 6.1 三个模式

```
        N 命令
 AUTO ──────────► MANUAL
   ▲                │
   │  A 命令        │ A 命令
   └────────────────┘

  任何模式 ──E──► ESTOP ──A 或 N──► 对应模式
```

- **AUTO**：状态机接管。收到 `N` 会先自动切进 MANUAL
- **MANUAL**：状态机**暂停**，动作由 `N` 决定。用于单独验证底盘方向表和机构
- **ESTOP**：四个轮 + 三个舵机立即停、动作码归 `00`，**必须收到明确的 `A` 或 `N` 才能退出**

进入 / 退出模式都发一条 `L` 日志。

### 6.2 ⚠️ 四道保险，一条都不能省

**① 遥控心跳超时**
MANUAL 模式下，**200 ms 内没收到 `N` 或 `H`，动作码立即归 `00` 刹车、拨轮停转**（模式保持 MANUAL，`fault` 置 bit3）。

> 蓝牙断了、电脑卡了、你手滑关了窗口——车立刻停。**没有这条，一次断连就可能把机构撞坏。**

**② 范围钳制：越界整行丢弃，不是钳到边界**

| 字段 | 合法范围 |
|---|---|
| `N` 的 code | 0 ~ 5 |
| `state` | 1 ~ 10 |
| `M` 模式字 | 0 ~ 3 |
| `J` 的 id | 0 ~ 2 |
| `J` 的 val（拨轮） | −1000 ~ +1000 |

越界 → 丢弃整行 + 回 `L,BAD_RANGE`。**数值离谱本身就说明数据有问题，钳到边界等于把错误吞掉了。**

**③ 校验不过整行丢弃**，只累加计数不回日志。

**④ 上电默认 AUTO 且动作码为 `00`**，不会一上电就跑。

## 8. `fault` 位定义

| 位 | 含义 |
|---|---|
| bit0 | 电机堵转 |
| bit1 | 视觉失效（`vision_lost` 持续超时） |
| bit2 | 电池低压 |
| bit3 | 遥控心跳超时 |
| bit4 | 蓝牙链路错误（校验错率过高 / 溢出） |
| bit5~7 | 保留 |

## 9. 参数表

**⚠️ F103 没有 FPU**，全部用 **int32 定点**传输。标注"×1000"的，界面上显示 1.234 就发 `1234`。

参数名规则：**大写 + 下划线，≤ 15 字符**。

| 名称 | 定标 | 含义 | 初值 | 范围 |
|---|---|---|---|---|
| `SPD_TARGET` | ×1 | **闭环目标：每 12 ms 的编码器计数** | 11 | 1 ~ 500 |
| `SPD_STEP` | ×1 | **占空比每 tick 的调整量** | 1 | 1 ~ 20 |
| `D_NEAR_MM` | ×1 | 远/近分界（车体中心基准） | 490 | 0 ~ 5000 |
| `D_BLIND_MM` | ×1 | 拨轮遮挡盲区 | 326 | 0 ~ 5000 |
| `ALIGN_TOL_C` | ×100 | 对准阈值 度：方位角小于它就停止转 | 100（=1.0°） | 1 ~ 6000 |
| `WALL_TRIG_MM` | ×1 | 碰壁换行触发距离 | 300 | 50 ~ 4000 |
| `ROW_PITCH_MM` | ×1 | 弓字形行距 | 1000 | 100 ~ 3000 |
| `WHEEL_L_MM` | ×1 | 半轴距 + 半轮距，里程推算用 | 待实测 | 10 ~ 1000 |
| `WHEEL_R_MM` | ×100 | 轮半径 ×100 mm（Φ75 → 3750） | 3750 | 500 ~ 20000 |
| `ENC_PPR` | ×1 | 编码器一圈脉冲数（四倍频后） | 待实测 | 1 ~ 200000 |
| `KNOB_SPD` | ×1 | 拨轮舵机工作转速 | 待定 | −1000 ~ 1000 |
| `TELEM_HZ` | ×1 | 遥测频率 Hz | 20 | 1 ~ 50 |

**v3 删掉的参数**（共 13 个）：`KP_V KI_V KD_V KP_W KI_W KD_W KP_VIS KD_VIS
V_MAX VY_MAX W_MAX V_CRUISE V_NEAR`。

原因：动作码方案下，四轮闭环是「计数不到目标就加占空、超了就减」的纯积分律，
没有 P/D 项可调；速度全局一档，几个限幅和巡航速度也没有作用点了。
**留着这些参数比删掉更糟**——上位机上摆一排拧了没反应的旋钮，
调试时会有人花一小时怀疑是不是链路坏了。要恢复连续速度控制时再一起加回来。

`SPD_TARGET` / `SPD_STEP` 这两个是新加的，对应原 `main.c` 里写死的 `11` 和 `++/--`。
**默认值与原来完全一致**，不改参数就是原来的行为；能改是为了让上位机在调
「车太慢 / 起步太抖」时有东西可拧。真要写死，把这两行从 `s_params[]` 删掉即可。

**⚠️ 当前控制律本身就是个纯积分器**，占空比就是累加量。`motion.c` 里已经把它
钳在 `0 ~ 100`（`MOTION_DUTY_MAX`），所以不会出现 `01-接口约定.md` §附录第 8 条
记录的 2024 届那个坑（低速堵转几秒后积分涨到几千、之后很久退不了饱和）。
遥测里的 `duty_*` 就是给你看这个的：**顶到 100 还追不上目标 = 负载或电池问题，
不是参数问题**。

**参数掉电不保存**（不写 Flash）。上位机负责在本地存一份，连上后用 `P` 批量下发。这样避免了 Flash 擦写次数问题，也让"一键恢复某组参数"变得很容易。

## 10. 典型时序

**连接时**

```
上位机 → Q*51
主控   → V,0.2.0,3,72000000*7E
主控   → K,SPD_TARGET,11*42
主控   → K,SPD_STEP,1*70
        …（全部 12 个参数）
主控   → T,...    （之后持续 20 Hz）
```

**改参数**

```
上位机 → P,SPD_TARGET,25*5E
主控   → K,SPD_TARGET,25*45     ← 确认，界面据此更新
```

越界会被钳到范围内再回读，回的是**实际生效值**，不是你发的值：

```
上位机 → P,SPD_TARGET,9999*59
主控   → K,SPD_TARGET,500*77    ← 钳到上限
```

**手动遥控**（界面按住方向键时以 50 ms 周期重发同一个码）

```
上位机 → N,01*63      ← 首条 N 自动切入 MANUAL
主控   → L,MODE MANUAL*59
上位机 → N,01*63      ← 每 50 ms 重发
        …
（松开按键，上位机改发 N,00 并停止重发）
        …200 ms 后没有任何 N 或 H
主控   → 动作码归 00 刹车、拨轮停，fault |= bit3
主控   → L,RC TIMEOUT*0A
```

**非法码**

```
上位机 → N,6*54
主控   → L,BAD RANGE*58         ← 整行丢弃，当前动作不变
```

**急停**

```
上位机 → E*45
主控   → L,ESTOP BY HOST*26
主控   → 动作码归 00、电机和三个舵机全停，进入 ESTOP
（此后只有 A 或 N 能解除）
```

## 11. 实现要点（主控端）

- **接收**：蓝牙所在串口（同学板子是 USART2，PD5/PD6 完全重映射；测试板是 UART5）中断里**只把字节塞进环形缓冲区**（256 B，大小取 2 的幂用位与取模；中断写 head、主循环读 tail，一写一读天然无锁），主循环取出来按 `\n` 组装成行再解析。
  **⚠️ 绝不能用阻塞轮询 `HAL_UART_Receive`**——115200 下一个字节只要 87 µs，轮询的空窗期内到达的字节会被覆盖（实测发 `government` 会收成 `governent`）。
- **发送**：`HAL_UART_Transmit_IT`，发之前先查 `gState != HAL_UART_STATE_READY` 就**跳过这一帧**，绝不阻塞主循环。丢帧计数上报。
- **中断里不做解析**，只入队。解析和响应都在主循环的时间片里做。
- `HAL_UART_ErrorCallback` 里清 ORE（F1 的写法是依次读 `SR` 再读 `DR`）并重新武装接收。
- 遥测由 50 ms 时间片触发；`TELEM_HZ` 改变时重算周期。
- **运动闭环由 `Motion_Tick()` 承担，节拍 12 ms**（`MOTION_TICK_MS`，与原 `main.c` 的 `HAL_Delay(12)` 一致）。
  主循环改成非阻塞时间片之后**不要再用 `HAL_Delay`**——遥测、命令解析、运动闭环三个节拍互不相同，
  一条 `HAL_Delay` 会把另外两个一起拖住。

### 11.1 `main.c` 接线（给主控同学）

原来的 `mode == 0/1/2/3` 四大块全部删掉，整个 `while(1)` 变成一个非阻塞时间片调度器。
**不要再用 `HAL_Delay`**——运动 12 ms、遥测 50 ms、命令解析每圈，三个节拍互不相同，
一条 `HAL_Delay` 会把另外两个一起拖住。

```c
/* USER CODE BEGIN Includes */
#include "motion.h"
#include "debug_link.h"
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
  Motion_Init();                    /* 里面已经含 DRV8833_Init 和四路编码器启动 */
  DebugLink_Init(&huart2);          /* 蓝牙所在串口。测试板上是 &huart5 */

  uint32_t t_motion = 0, t_telem = 0;
/* USER CODE END 2 */

  while (1)
  {
    /* USER CODE BEGIN 3 */
    uint32_t now = HAL_GetTick();

    DebugLink_Poll();               /* 每圈都跑：解析命令、查心跳超时。不阻塞 */

    /* --- 运动闭环 12 ms --- */
    if (now - t_motion >= MOTION_TICK_MS) {
      t_motion = now;

      const dbg_ctrl_t *ctrl = DebugLink_Ctrl();
      if (ctrl->mode == DBG_MANUAL) {
        Motion_Set(ctrl->code);           /* 上位机遥控 */
      } else if (ctrl->mode == DBG_ESTOP) {
        Motion_Set(MOTION_BRAKE);
      } else {
        Motion_Set(app_wanted_code());    /* AUTO：你的状态机给出动作码 */
      }

      /* 上位机改了参数就同步进来 */
      Motion_SetTarget((int16_t)DebugLink_Param(P_SPD_TARGET));
      Motion_SetStep((uint8_t)DebugLink_Param(P_SPD_STEP));

      Motion_Tick();
    }

    /* --- 遥测 50 ms --- */
    if (now - t_telem >= 50u) {
      t_telem = now;

      dbg_telem_t tm;
      memset(&tm, 0, sizeof(tm));         /* 需要 #include <string.h> */

      int16_t cnt[WHEEL_COUNT];  Motion_GetCount(cnt);
      uint8_t duty[WHEEL_COUNT]; Motion_GetDuty(duty);
      tm.cnt_lf = cnt[WHEEL_LF]; tm.cnt_lb = cnt[WHEEL_LB];
      tm.cnt_rf = cnt[WHEEL_RF]; tm.cnt_rb = cnt[WHEEL_RB];
      for (int i = 0; i < 4; i++) tm.duty[i] = duty[i];
      tm.cmd_code = Motion_Get();

      /* 下面这些等对应模块接上了再填，暂时留 0 */
      /* tm.yaw_c = ...; tm.vis_class = ...; tm.tof[0] = ...; tm.state = ...; */

      DebugLink_SendTelem(&tm);
    }
    /* USER CODE END 3 */
  }
```

⚠️ **`}` 收 `while` 的那一行必须写在 `/* USER CODE END 3 */` 上面**，
写到下面去的话，下一次 CubeMX 重新生成会把它吃掉，然后报
`expected declaration or statement at end of input` —— 这个坑已经踩过两次。

⚠️ 中断回调里要分发给对应的模块：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == UART4)  { /* 视觉那条线 */ }
  else if (huart->Instance == USART2) { DebugLink_OnRxByte(); }
}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART2) { DebugLink_OnError(); }
}
```

⚠️ USART2 走 PD5/PD6 是**完全重映射**，`stm32f1xx_hal_msp.c` 里必须有
`__HAL_AFIO_REMAP_USART2_ENABLE();`，漏了的话 PD5/PD6 上什么都收不到。

## 13. ⚠️ 已发现的文档冲突（需要全组确认）

**① PPT《引脚接线表-1》与 `smart_car.ioc` 冲突，照 PPT 接线会短路。**

| | PPT | 实际 .ioc |
|---|---|---|
| TIM2 四路 PWM | PA0 / PA1 / PA2 / PA3 | **PA15 / PB3 / PA2 / PA3** |
| PA0 / PA1 | L298N_LEFT 的 IN1/IN2 | **TIM5 编码器（左后轮 A/B）输入** |

代码是能跑的那份，**以 `.ioc` 为准，PPT 那张表要改**。

**② `01-接口约定.md` §6c 关于超声的论证已过时。**
真实清单里 HC-SR04 数量 = 0（仅备用），ToF 换成 **TOF400C-4M（VL53L1X，量程 4 m）× 3**。
原文"侧向 ToF 在弓字形第二趟会超量程、须用侧前超声兜底"的前提不成立了——
4 m 量程覆盖 2×3 m 场地绰绰有余，碰壁判据可以完全走 ToF。**6c 节要重写。**

**③ `app_state.h` 里的 `us_mm[3]`、`color_hit` 需要处理。**
- `us_mm[3]`：超声砍了，字段可以删或保留置 0
- `color_hit`：**真实清单里没有颜色传感器** —— 卸料的"三层独立判据"里"车底颜色"这一层没有硬件支撑了，
  只剩视觉方位角 + ToF 两层。这个降级要评估。

**④ `app_state.h` 里的 `cmd_v` / `cmd_w_c` 与 v3 不一致。**
v3 之后主控对外只用一个动作码，`app_state.h` 里那两个连续量应当改成
`uint8_t cmd_code`，否则状态机和运动模块之间会各说各话。

**⑤ ToF ×3 的安装位置（前 / 侧 / 后？）** 尚未确定，定了之后回来补 `tof0~2` 的语义。

**⑥ TCA9548 I2C 多路复用器**：三个 VL53L1X 默认 I2C 地址相同，所以要用它分通道。
主控端读 ToF 前要先写 TCA9548 选通道。目前 `.ioc` 里 **I2C 还没配**。

**⑦ 动作集里没有「后退」。** 见 §5.1.3。抓完料退出、撞墙脱困这两处目前无解，
加一个 `06` 只要一行表项，但属于接口约定，要全组定。

**⑧ 视觉伺服（状态 3）在 v3 下降级为脉冲对准。**
只有「左转 / 右转」两档定速，对准目标只能靠「转一下、看一眼、再转一下」，
在目标两侧来回振荡，精度受 `ALIGN_TOL_C` 和单次脉冲时长共同限制。
v2 里按方位角连续给角速度的做法（`KP_VIS` / `KD_VIS`）已随 `S` 一起删除。
**如果实测发现对不准，这里是第一个要回退的地方**——恢复 `S` 命令即可，
`motion.c` 的方向表可以继续用。
