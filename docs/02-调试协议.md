# 02 · 调试协议（主控 ↔ 上位机）

> 配套 `01-接口约定.md`。那份管 **视觉↔主控**，这份管 **主控↔电脑上位机**。
> 两份都改动时必须同步通知全组。
>
> 版本 **v2**，2026-08-25。
> v2 依据《详细设计汇报》和真实《物品清单》重写：三自由度麦轮遥控、超声改 ToF×3、
> 新增三路总线舵机控制。

---

## 0. 一句话

蓝牙串口上跑 **ASCII 行协议**：主控 20 Hz 往上位机推一行遥测，上位机随时往下发单行命令，每行末尾带一个异或校验。

---

## 1. 物理层

| 项 | 值 |
|---|---|
| 主控侧 | **USART2 完全重映射：PD5 = TX、PD6 = RX** |
| 模块 | HC-05，名字 `CAR_DBG`，配对码 `1234`，ROLE=0（从机） |
| 波特率 | **115200**，8 数据位，无校验，1 停止位 |
| 电脑侧 | 蓝牙配对后的**「传出」**虚拟串口（本机是 `COM13`） |

> HC-05 的 VCC 只能给 **5 V**（下限 3.6 V），逻辑电平 3.3 V，接 STM32 直连、不用电平转换。

---

## 2. 为什么用文本而不是二进制帧

跟视觉链路**故意做相反的选择**：

| | 视觉链路（OpenMV，二进制定长帧） | 调试链路（蓝牙，ASCII 行） |
|---|---|---|
| 谁在读 | 机器对机器 | **人在读** |
| 频率 | 25 Hz，要省带宽 | 20 Hz，带宽富余 |
| 出错时 | 只能靠调试器猜 | **肉眼直接看懂** |
| 手动测试 | 得写脚本 | **串口助手打一行就能测** |

调试通道的第一属性是"出问题时你能看懂"，为这个牺牲一点带宽非常划算。

**带宽核算**：遥测行约 126 字节 × 20 Hz = **2.5 KB/s**，占 115200 bps 的 22%。HC-05 的 SPP 实测吞吐通常 3～8 KB/s，留有余量。

---

## 3. 行格式通则

```
<类型字符> [ , <字段> ]* * <校验> \n
```

- **行尾** `\n`（0x0A）。`\r` 一律忽略，所以 `\r\n` 也能用。
- **校验** `*` 后跟**两位大写十六进制**，等于**行首到 `*` 之前所有字符的逐字节异或**（不含 `*` 本身）。
- 行内**不允许**出现 `\n`、`*`（校验位除外）。
- **单行最长 160 字节**，超长整行丢弃。
- 校验不通过 → **整行丢弃**，只累加错误计数，**不回错误日志**（否则线路差时会互相刷屏）。

### 校验计算示例

对 `E`：`0x45` → 校验 `45`，完整行是 `E*45\n`

C 语言实现：

```c
static uint8_t line_xor(const char *s, uint16_t n)
{
    uint8_t c = 0;
    for (uint16_t i = 0; i < n; i++) c ^= (uint8_t)s[i];
    return c;
}
```

### 向后兼容规则（重要）

- **新字段只允许追加在行尾。**
- 接收方解析时：**字段数不足 → 丢弃整行；字段数超出 → 忽略多余的。**

这样一端升级了另一端不用同步改，不会互相打架。协议版本号在 `V` 帧里报。

## 4. 上行：主控 → 上位机

### 4.1 `T` 遥测帧（20 Hz）

```
T,<1>,<2>,...,<25>*XX
```

| # | 字段 | 类型 | 单位 / 含义 |
|---|---|---|---|
| 1 | `ms` | uint32 | 主控运行时间，ms |
| 2 | `v_lf` | int16 | **左前**轮速，mm/s |
| 3 | `v_lb` | int16 | **左后**轮速 |
| 4 | `v_rf` | int16 | **右前**轮速 |
| 5 | `v_rb` | int16 | **右后**轮速 |
| 6 | `yaw_c` | int16 | IMU 航向 ×100 度（相对值） |
| 7 | `vis_class` | uint8 | 0 无 / 1 红方块 / 2 黄圆柱 / 3 目标区 |
| 8 | `vis_bear_c` | int16 | 视觉方位角 ×100 度，左负右正 |
| 9 | `vis_dist` | uint16 | 视觉距离 mm，**65535 = 无效** |
| 10 | `vis_conf` | uint8 | 置信度 0~100 |
| 11 | `vision_lost` | uint8 | 0/1，100 ms 无视觉帧置 1 |
| 12 | `tof0` | uint16 | ToF ①，mm，**0 = 无效/超量程** |
| 13 | `tof1` | uint16 | ToF ② |
| 14 | `tof2` | uint16 | ToF ③ |
| 15 | `intake` | uint16 | 入料口累计计数 |
| 16 | `state` | uint8 | 任务状态 1~10（见 §7） |
| 17 | `n_col` | uint8 | 已收数量 |
| 18 | `fault` | uint8 | 故障位（见 §8） |
| 19 | `cmd_vx` | int16 | 期望**前进**速度 mm/s（负 = 后退） |
| 20 | `cmd_vy` | int16 | 期望**横移**速度 mm/s（**正 = 向左**） |
| 21 | `cmd_w_c` | int16 | 期望角速度 ×100 度/s（正 = 逆时针 / 左转） |
| 22 | `srv_rail` | int16 | 导轨舵机当前值 |
| 23 | `srv_knob` | int16 | 拨轮舵机当前值 |
| 24 | `srv_push` | int16 | 推杆舵机当前值 |
| 25 | `mode` | uint8 | 0 = AUTO，1 = MANUAL，2 = ESTOP |

**⚠️ 轮序命名坑**：队友代码里 `LEFT_FORWARD` / `LEFT_BACKWARD` 指的是**左前轮 / 左后轮**，
不是"前进 / 后退"。协议里统一用 `lf / lb / rf / rb`，避免歧义。

**⚠️ ToF 三个的安装位置（前 / 侧 / 后？）还没定**，`tof0~2` 的语义等机械装配后确定，
在这里补一行说明。TOF400C-4M（VL53L1X）量程 4 m，覆盖 2×3 m 场地绰绰有余。

**没有超声波字段** —— 真实清单里 HC-SR04 数量为 0（仅供备用）。
`01-接口约定.md` §6c v4 那段"前向靠超声、侧向 ToF 会超量程"的论证**已经过时**：
ToF 换成 4 m 量程后，覆盖搜索的碰壁判据可以完全走 ToF。**那一节要跟着改。**

示例：

```
T,12345,200,198,201,199,-1523,1,-1234,850,90,0,1200,430,0,3,4,0,0,200,0,0,0,500,0,1*3E
```

### 4.2 `V` 握手帧

```
V,<fw_ver>,<proto_ver>,<sysclk_hz>*XX
```

上电后发一次；收到下行 `Q` 时也发一次，**紧接着把所有参数用 `K` 帧全部回读一遍**。

示例：`V,0.3.1,1,72000000*2C`

### 4.3 `K` 参数回读帧

```
K,<NAME>,<value>*XX
```

**每次收到 `P` 改参数后必须回一条 `K` 确认**——上位机据此更新界面显示，形成闭环。改失败（参数名不认识 / 越界）也要回 `K` 带**当前实际值**，让界面能自动纠正。

示例：`K,KP_V,1200*35`

### 4.4 `L` 日志帧

```
L,<text>*XX
```

`text` 内**不得含** `,` `*` `\r` `\n`，长度 ≤ 100。

示例：`L,STATE 2->3*4F`、`L,ESTOP BY HOST*1B`

## 5. 下行：上位机 → 主控

| 命令 | 格式 | 说明 |
|---|---|---|
| **遥控** | `S,<vx>,<vy>,<w>*XX` | **三自由度**：前进 / 横移 / 自转，见下 |
| 心跳 | `H*XX` | 遥控模式下保活，不改速度 |
| **舵机** | `J,<id>,<val>*XX` | id：0 = 导轨，1 = 拨轮，2 = 推杆 |
| 设参数 | `P,<NAME>,<value>*XX` | value 为 **int32**，多数是 ×1000 定点（见 §9） |
| 强制状态 | `G,<state>*XX` | 直接切到 1~10 某个状态 |
| 视觉模式 | `M,<0-3>*XX` | 转发给 OpenMV 的模式字（见 `01-接口约定.md` §2b） |
| 请求同步 | `Q*XX` | 主控回一条 `V` + 全部 `K` |
| 急停 | `E*XX` | 立刻停所有电机和舵机 |
| 回自动 | `A*XX` | 交还给状态机 |

### 5.1 `S` 三自由度速度（麦克纳姆轮）

```
S,<vx>,<vy>,<w>*XX
```

| 分量 | 单位 | 正方向 | 范围 |
|---|---|---|---|
| `vx` | mm/s | **车头方向为正** | −600 ~ +600 |
| `vy` | mm/s | **向左为正** | −600 ~ +600 |
| `w` | ×100 度/s | **逆时针（左转）为正** | −18000 ~ +18000 |

坐标系沿用 `01-接口约定.md` §1：**x 向前、y 向左、逆时针为正**。

**为什么必须有 `vy`**：底盘是 Φ75 麦克纳姆轮 ×4 全向底盘。《详细设计汇报》第 4 页写着
"麦轮底盘为后续**对准目标—贴近目标—顶靠卸货区**提供姿态调整能力"——角落对接要贴两面墙，
靠的就是不改变朝向的横移。只给 `vx/w` 等于把麦轮当差速车用，最值钱的能力浪费掉。

**麦轮逆运动学**（主控端实现，`L` 为半轴距 + 半轮距之和）：

```
v_lf = vx - vy - L*w
v_rf = vx + vy + L*w
v_lb = vx + vy - L*w
v_rb = vx - vy + L*w
```

⚠️ **符号取决于四个轮子辊子的实际朝向（O 型 / X 型）**，装好后必须**实测**：
逐个自由度单独给指令（只给 `vx`、只给 `vy`、只给 `w`），看车是不是按预期走。
四个符号里错一个，横移就会变成原地打转。**这是麦轮车最常见的翻车点。**

### 5.2 `J` 舵机命令

```
J,<id>,<val>*XX
```

| id | 舵机 | `val` 含义 | 范围 |
|---|---|---|---|
| 0 | `SERVO_SLIDE_RAIL` 导轨 | 目标位置 | 待标定 |
| 1 | `SERVO_KNOB` 拨轮 | **连续旋转速度**（STS3032 轮式模式），负=反转脱困 | −1000 ~ +1000 |
| 2 | `SERVO_PUSH_ROD` 推杆 | 目标位置 | 待标定 |

三个都是飞特 **STS3032** 单轴 360° 磁编码总线舵机，经 URT-2 驱动板走串口
（导轨 + 拨轮 挂 UART4，推杆 挂 UART5）。

**`J` 命令只在 MANUAL 模式下生效**，AUTO 模式下由状态机控制，收到 `J` 回 `L,J IGNORED AUTO`。

## 6. 运行模式与安全机制

### 6.1 三个模式

```
        S 命令
 AUTO ──────────► MANUAL
   ▲                │
   │  A 命令        │ A 命令
   └────────────────┘

  任何模式 ──E──► ESTOP ──A 或 S──► 对应模式
```

- **AUTO**：状态机接管，`S` 命令被忽略之前先切 MANUAL
- **MANUAL**：状态机**暂停**，速度由 `S` 决定。用于单独验证底盘运动学和机构
- **ESTOP**：四个轮 + 三个舵机立即停，**必须收到明确的 `A` 或 `S` 才能退出**（不会被下一条 `S` 悄悄恢复以外的任何方式解除）

进入 / 退出模式都发一条 `L` 日志。

### 6.2 ⚠️ 四道保险，一条都不能省

**① 遥控心跳超时**
MANUAL 模式下，**200 ms 内没收到 `S` 或 `H`，三个速度分量立即全部归零、拨轮停转**（模式保持 MANUAL，`fault` 置 bit3）。

> 蓝牙断了、电脑卡了、你手滑关了窗口——车立刻停。**没有这条，一次断连就可能把机构撞坏。**

**② 范围钳制：越界整行丢弃，不是钳到边界**

| 字段 | 合法范围 |
|---|---|
| `vx` / `vy` | −600 ~ +600 mm/s |
| `w` | −18000 ~ +18000（±180 °/s） |
| `state` | 1 ~ 10 |
| `M` 模式字 | 0 ~ 3 |
| `J` 的 id | 0 ~ 2 |
| `J` 的 val（拨轮） | −1000 ~ +1000 |

越界 → 丢弃整行 + 回 `L,BAD_RANGE`。**数值离谱本身就说明数据有问题，钳到边界等于把错误吞掉了。**

**③ 校验不过整行丢弃**，只累加计数不回日志。

**④ 上电默认 AUTO 且速度为 0**，不会一上电就跑。

## 10. 典型时序

**连接时**

```
上位机 → Q*51
主控   → V,0.3.1,1,72000000*2C
主控   → K,KP_V,1200*35
主控   → K,KI_V,80*7B
        …（全部参数）
主控   → T,...    （之后持续 20 Hz）
```

**调 PID**

```
上位机 → P,KP_V,1500*29
主控   → K,KP_V,1500*3F      ← 确认，界面据此更新
主控   → L,PARAM KP_V SET*1D
```

**手动遥控**（界面按住方向键时以 50 ms 周期重发）

```
上位机 → S,200,0,0*5C   ← 首条 S 自动切入 MANUAL
主控   → L,MODE MANUAL*33
上位机 → S,200,0,0*5C   ← 每 50 ms
        …
（松开按键，停发）
        …200 ms 后
主控   → 三个速度分量归零、拨轮停，fault |= bit3
```

**急停**

```
上位机 → E*45
主控   → L,ESTOP BY HOST*1B
主控   → 电机、拨轮全停，进入 ESTOP
```

## 11. 实现要点（主控端）

- **接收**：USART2（PD5/PD6，完全重映射）中断里**只把字节塞进环形缓冲区**（256 B，大小取 2 的幂用位与取模；中断写 head、主循环读 tail，一写一读天然无锁），主循环取出来按 `\n` 组装成行再解析。
  **⚠️ 绝不能用阻塞轮询 `HAL_UART_Receive`**——115200 下一个字节只要 87 µs，轮询的空窗期内到达的字节会被覆盖（实测发 `government` 会收成 `governent`）。
- **发送**：`HAL_UART_Transmit_IT`，发之前先查 `huart2.gState != HAL_UART_STATE_READY` 就**跳过这一帧**，绝不阻塞主循环。丢帧计数上报。
- **中断里不做解析**，只入队。解析和响应都在主循环的时间片里做。
- `HAL_UART_ErrorCallback` 里清 ORE（F1 的写法是依次读 `SR` 再读 `DR`）并重新武装接收。
- 遥测由 50 ms 时间片触发；`TELEM_HZ` 改变时重算周期。

## 13. ⚠️ 已发现的文档冲突（需要全组确认）

**① PPT《引脚接线表-1》与 `smart_car.ioc` 冲突，照 PPT 接线会短路。**

| | PPT | 实际 .ioc |
